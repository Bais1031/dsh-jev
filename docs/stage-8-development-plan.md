# dsh-jev 阶段 8：评估与发布计划

## 摘要

阶段 8 把已经可用的 Jev 路由器推进到可测量、可发布和可从插件市场安装的版本。工作从真实 API 连通性开始，随后建立本地指标、校准方法、发布文档和持续集成，最后发布 npm 包并提交社区目录。指标默认保留在本地；任何远程遥测都不属于本阶段。每个子阶段必须通过自己的验收，才能进入依赖它的下一阶段。

## 完成定义

阶段 8 只有在以下结果同时成立时才算完成：

- 用户能在插件配置页测试 Jev 连接，并获得不包含凭证的结构化结果。
- 插件能基于 Session 记录生成本地 JSON 和 Markdown 评估报告。
- 报告明确区分观测值、估算值和缺少标签时不可计算的指标。
- 真实 API、路由模式、故障回退和干净安装均有验收证据。
- 支持的 DSH profile 范围、数据发送范围、升级和卸载方法有明确文档。
- npm 包、Git tag 和 GitHub Release 指向同一版本及同一发布内容。
- 社区目录可以发现、安装、启用、配置和卸载该版本。

## 8.1：真实 API 与连接测试

本阶段让用户先验证凭证、网络、endpoint、模型和 Jev 响应协议，再启用路由。连接测试不得依赖主 Agent 自行选择 `jev_decide` 工具。

### 开发内容

- 在插件配置页增加“测试连接”操作和明确的成功、失败、进行中状态。
- 通过 Host 端调用现有 `DecisionService`，浏览器不读取 API 密钥。
- 返回 provider、model、延迟和 token usage；失败返回稳定错误码和可操作说明。
- 禁止在浏览器响应、日志、Session 记录和错误消息中包含 API 密钥或原始认证响应。
- 增加真实 API 手动验收步骤；自动测试继续使用模拟 HTTP，不依赖网络或真实凭证。

### 验收条件

- 有效凭证显示成功结果，并能完成一次 Boolean 和 Choice 混合决策。
- 缺失凭证、401/403、429、超时、网络失败和无效响应显示对应稳定错误码。
- 重复点击、取消、页面卸载和插件卸载不会遗留请求或产生重复成功提示。
- 连接测试不会改变路由模式，也不会执行工具或外部操作。
- 类型检查、单元测试、发布构建和 Web 浏览器验收通过。

## 8.2：本地指标与报告

本阶段把已有的路由审计记录折叠为本地统计结果。`metricsEnabled` 控制聚合与报告，不得关闭重放和故障诊断所需的路由审计记录。

### 开发内容

- 定义带版本号的指标投影或离线分析器，按 Session、时间范围和路由模式读取记录。
- 关联路由请求、Jev 结果、Advisory/Automatic 结果以及同一步的 LLM usage。
- 输出机器可读 JSON 和便于人工审查的 Markdown 报告。
- 统计请求数、成功率、失败码、Jev token、下游 LLM token、P50/P95 延迟、推荐分布、自动应用率、回退率和用户覆盖率。
- 把模型切换次数作为观测值；只有存在明确基线和实际 usage 时才计算 token 节省估算。
- 报告不得包含 API 密钥；用户文本默认不进入聚合结果。

### 验收条件

- 固定 Session fixture 生成确定性的 JSON 和 Markdown 输出。
- 空数据、部分日志、失败记录、旧策略版本和未知可忽略记录均有定义明确的结果。
- P50/P95、比率和 token 合计使用测试固定的计算方法。
- `metricsEnabled: false` 停止新增聚合结果，但路由与必要审计记录继续工作。
- 报告明确标记样本范围、策略版本、不可计算字段和估算方法。

## 8.3：评估数据与概率校准

本阶段为 Jev 概率建立可审查的标签来源。没有标签时，插件不得展示 Brier Score、ECE 或“推荐正确率”等推断性结论。

### 开发内容

- 定义固定任务评估集，覆盖 fast、standard、deep、ask-user、低风险和高风险场景。
- 记录 Advisory 接受或拒绝、显式用户反馈以及评估集预期路线等标签来源。
- 分别计算路线选择和风险分类的 Brier Score、ECE、覆盖率及样本量。
- 比较候选置信度与概率差阈值，但不根据少量在线样本自动修改用户配置。
- 建立评估数据的隐私、保留和删除规则。

### 验收条件

- 校准计算对固定输入产生确定结果，并覆盖空桶、小样本和缺失标签。
- 报告区分用户偏好、任务结果和人工标注，不把其中一种当作全部正确性。
- 每个校准指标同时显示样本量和标签来源。
- Automatic 的默认阈值变更必须由评估证据支持，并更新配置说明和回归测试。

## 8.4：发布文档

本阶段让首次安装者能够理解数据流、安全限制和恢复方法。README 保留最短使用入口，详细说明放入 `docs/` 并由 README 链接。

### 开发内容

- 增加真实 API 连接测试、Shadow 验证、Advisory 验证和 Automatic 安全启用指南。
- 增加隐私说明，列出发送给 TypeSafe 的字段、本地记录内容和不记录的凭证内容。
- 增加指标解释，区分观测值、估算值和需要标签的校准指标。
- 增加升级、卸载、凭证轮换、常见错误码和故障排查指南。
- 准备中英文市场名称、简介、详细描述、类别、标签和截图文案。

### 验收条件

- 文档中的命令、配置和安装路径均在当前发布候选版本上执行验证。
- README 能在不复制详细参考的前提下链接全部用户任务。
- 隐私说明明确当前版本没有远程指标遥测。
- 升级和卸载步骤不会删除用户 Session 或其他插件数据。

## 8.5：CI、干净安装与 Headless 决策

本阶段固定发布前质量检查，并解决当前 Headless profile 会禁用 DSH Credentials 服务的问题。发布支持范围必须与实际安装结果一致。

### 开发内容

- 增加 Node 22 和 Node 24 的 typecheck、test、build、pack 和安装 smoke CI。
- 检查发布包只包含允许的源码产物、声明、文档、许可证和 bundle patch。
- 在全新的 DSH Web profile 中验证安装、启用、配置、停用和卸载。
- 选择并实现一种 Headless 策略：安全支持启动环境凭证，或明确声明不支持 stock Headless profile。
- 增加凭证泄露扫描，并确认正常测试不访问真实 API。

### 验收条件

- CI 在干净 checkout 上通过，不依赖本地 `lib/`、全局包或未提交文件。
- 发布 tarball 能在支持的 profile 中直接运行，不执行安装脚本。
- Headless 的代码、测试、README、市场元数据和兼容声明采用同一个结论。
- 安装、停用和卸载后没有残留 Cordis 注册或后台任务。

## 8.6：npm 与 GitHub 发布

本阶段把已验收的提交转换为可重复安装的稳定版本。发布前必须先保存阶段 5 至阶段 8 的全部源码、测试和文档。

### 开发内容

- 提交并推送尚未进入远端的路由、配置和阶段 8 代码。
- 在线确认 npm 包名和发布权限，再移除 `private: true`。
- 确定版本号，生成最终 tarball，并从 tarball 安装进行最后 smoke test。
- 发布 npm 包，创建相同版本的 Git tag 和 GitHub Release。
- 发布说明包含功能、兼容范围、数据发送、安全限制、已知限制和升级步骤。

### 验收条件

- npm registry、Git tag、GitHub Release 和 `package.json` 使用同一版本。
- npm 安装获得的文件与已验收 tarball 一致。
- 一个全新 Web profile 能从 npm 安装并通过连接测试。
- 发布记录不包含凭证、测试 Session、用户输入或本地绝对路径。

## 8.7：插件市场收录

本阶段把稳定 npm 版本提交到社区目录。`awesome-dsh-plugin` 是条目来源；`dsh-market` 应用仓库不是插件条目的提交目标。

### 开发内容

- 按目录格式准备中英文标题、描述、类别、标签、版本范围和安装来源。
- 提交 `awesome-dsh-plugin` 条目，并处理目录校验或评审反馈。
- 等待目录同步后检查 `dsh-plugin-catalog` format-1 索引。
- 在 DSH Discover 页面完成发现、安装、启用、配置、更新和卸载验收。

### 验收条件

- 市场条目指向已发布的稳定 npm 版本和正确的源代码仓库。
- DSH Discover 显示正确名称、说明、版本、兼容范围和图标。
- 从市场安装后的插件能通过连接测试和 Shadow 路由验证。
- 卸载不会删除 DSH Credentials 中由用户管理的密钥，文档明确说明凭证清理方式。

-----

## 总验收

阶段 8 的最终报告应逐项列出实际执行的命令、真实 API 手动测试、浏览器验收、CI 运行、npm 发布、GitHub Release 和市场安装结果。任何未执行的外部操作必须标记为待验收，不能用本地构建成功替代。

建议最终报告至少包含以下结果：

| 范围 | 必须提供的证据 |
| --- | --- |
| 功能 | 连接测试、Shadow、Advisory、Automatic 和三类回退结果 |
| 指标 | 固定数据集报告、计算方法、样本量和不可计算项 |
| 安全 | 凭证不泄露、危险操作不被路由授权、故障可见 |
| 兼容 | Node 与 DSH 版本矩阵、支持的 profile |
| 发布 | tarball、npm 版本、Git tag、GitHub Release |
| 市场 | 目录条目、format-1 索引、Discover 安装与卸载 |

## 非目标

- 阶段 8 不建立远程遥测服务。
- 阶段 8 不让 Jev 决策授权删除、付款、发布、凭证或权限操作。
- 阶段 8 不根据未标注的在线流量自动调整安全阈值。
- 阶段 8 不向 `dsh-market` 应用仓库直接提交插件条目。

## Dev Note

以下事项仍需在对应子阶段确定，不构成当前行为承诺：npm 包名可用性、Headless 凭证方案、token 节省基线方法，以及市场截图的最终内容。
